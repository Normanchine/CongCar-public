# 分割后处理去噪（连通域过滤）

> 版本: v1.0 | 涉及: `SegmentationTask` / `SegmentationConfig`
> 核心: 在语义分割输出 mask 上做连通域过滤，剪掉长宽不足阈值的干扰碎片

## 1. 问题

赛道上有干扰物（线、杂物等），语义分割把干扰物也分割成了"赛道"，导致 mask 上出现**一块块碎片**（小连通区域）。

这些碎片会污染巡线：
- `extractBoundary` 把碎片边缘当成赛道边界 → 边界线乱跳 → 转向抖动
- 鸟瞰图里碎片与真实赛道粘连或紧邻时，边界提取结果被拉偏

## 2. 方案：源头去噪（连通域过滤）

在**语义分割后处理阶段**（模型输出刚转成 mask 时）清除碎片，而不是在鸟瞰图里处理：

```
NPU 推理 → argmax → mask(512×192) → 连通域过滤 → resize 原图 → publish
                              ↑
                         这里插入
```

**为什么放源头**：
- **一次过滤，处处干净**：所有下游（巡线场景 + 显示叠加）拿到的都是干净 mask
- 放鸟瞰图则每个场景都要过一遍，且污染已经传播到了边界提取
- 推理分辨率(512×192)更小，过滤更快（<1ms）

## 3. 过滤逻辑

```cpp
// SegmentationTask.cpp，argmax 之后、resize 之前
if (seg_cfg.min_region_px > 0) {
    cv::Mat labels, stats, centroids;
    int ncomp = cv::connectedComponentsWithStats(mask, labels, stats, centroids);
    for (int i = 1; i < ncomp; ++i) {   // 0=背景
        int w = stats.at<int>(i, cv::CC_STAT_WIDTH);
        int h = stats.at<int>(i, cv::CC_STAT_HEIGHT);
        if (w < seg_cfg.min_region_px || h < seg_cfg.min_region_px)
            mask.setTo(0, labels == i);   // 长宽任一不足 → 剪掉
    }
}
```

**判定规则**：某连通块**有效 ⟺ 宽 ≥ N 且 高 ≥ N**（`N = min_region_px`）
- 宽、高任一不足 → 判定为干扰碎片 → 该块像素置 0
- 长宽都满足 → 保留为有效赛道

> 注意：细长条（如宽 200、高 3px 的横线）也会被移除——它同样不是有效赛道。

## 4. 参数

| 参数 | 位置 | 默认值 | 说明 |
|------|------|--------|------|
| `min_region_px` | `SegmentationConfig` | 10 | 连通域长宽的最小像素数；**0=不过滤** |

**坐标系注意**：过滤发生在推理分辨率（512×192）上，所以 `min_region_px` 是 **512×192 里的像素**，比显示/原图（640×240）的像素小约 1.25 倍。实测时按观察到的碎片大小调。

**调参指引**：
- 碎片残留多 → 调大 `min_region_px`（如 20）
- 真实赛道被误剪（贴边细赛道被当碎片）→ 调小（如 5）
- 赛道过窄时注意：真实赛道在 512×192 里宽度有限，阈值太大会剪掉真赛道

## 5. 效果

- 干扰碎片从 mask 源头被清除，边界提取只看到连续赛道 → 巡线更稳
- 显示（原图分割叠加 + 鸟瞰图）同步干净，便于观察
- 每帧耗时 <1ms（512×192 连通域分析），无性能压力

## 6. 文件改动

| 文件 | 改动 |
|------|------|
| `SegmentationConfig`(Config.h) | 加 `min_region_px = 10` |
| `ConfigLoader.h` | 序列化 `min_region_px`（j.contains 兼容旧配置） |
| `default.json` | 分割段加 `"min_region_px": 10` |
| `SegmentationTask.cpp` | argmax 后、resize 前插入连通域过滤 |

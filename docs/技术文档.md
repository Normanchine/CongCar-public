## 1. 项目概述

基于 RK3588 (Orange Pi 5B) 的嵌入式智能车视觉上位机，C++17 实现。通过多线程流水线完成**共享内存帧采集 → 语义分割 → 目标检测 → 路径规划与控制 → 串口指令下发**的完整闭环。所有计算均在板端实时完成。

### 1.1 硬件平台

| 组件 | 型号 |
|------|------|
| 主控 | RK3588 (Orange Pi 5B)，4×A76 + 4×A55，6 TOPS NPU |
| 摄像头 | Python 服务端采集，POSIX 共享内存传递 |
| 下位机 | STM32 底盘控制板，UART 串口通信 |

### 1.2 核心技术栈

| 层级 | 技术 |
|------|------|
| 语言标准 | C++17 |
| AI 推理 | Rockchip RKNN C API (librknnrt.so)，三核 NPU 独立调度 |
| 视觉库 | OpenCV 4.x（图像处理、透视变换） |
| 配置 | nlohmann/json（JSON ↔ C++ struct 手动序列化，`j.contains` 向后兼容） |
| 编译 | CMake 3.16+ |
| 模型 | 语义分割（PP-LiteSeg 512×256）+ 目标检测（PP-YOLOE 640×256, 7类），RKNN INT8 量化 |

### 2.5 流水线时序

```
  Seg 双核流水线 (Core1+Core2 交替):
  Core1: [帧0]─infer─[帧2]─infer─[帧4]─infer─...
  Core2: ──[帧1]─infer─[帧3]─infer─[帧5]─infer─...
          │     │     │     │     │     │
  get:    └─帧0─┘     └─帧1─┘     └─帧2─┘
           publish       publish       publish

  吞吐: 单核~50fps → 双核~80fps
  单帧推理延迟: 25ms (双核并行时共享总线，略增)
  总耗时(含等待): ~2ms (另一核在后台跑，前台无等待)


  Det 流水线 (RKNNEngine Core0, 单实例, submit/get 异步):
  ┌─────┐     ┌─────┐     ┌─────┐
  │帧 N │     │帧N+1│     │帧N+2│
  └──┬──┘     └──┬──┘     └──┬──┘
     │           │           │
     ▼           ▼           ▼
  submit(N)  submit(N+1) submit(N+2)
     │           │           │
     │ infer N   │ infer N+1 │ infer N+2
     │ (Core0)   │ (Core0)   │ (Core0)
     ▼           ▼           ▼
  get(N)      get(N+1)    get(N+2)
  post(N)     post(N+1)   post(N+2)
     ▼           ▼           ▼
  publish(N)  publish(N+1) publish(N+2)


  ControlTask (事件驱动, 由 SegTask 唤醒):
       Seg notify          Seg notify
          ↓                    ↓
  ┌────┐  ~22ms  ┌────┐  ~22ms  ┌────┐
  │wake│  sleep  │wake│  sleep  │wake│  ...
  │run │         │run │         │run │
  │TX  │         │TX  │         │TX  │
  └────┘         └────┘         └────┘
   ↑ 无新数据时超时 50ms 兜底唤醒
   CPU 等待期间零占用
```

### 2.6 通信机制

| 机制 | 承载数据 | 模式 | 适用场景 |
|------|----------|------|----------|
| `FrameQueue<T>` | cv::Mat 帧 | 环形缓冲(容量3)，`tryConsume()` 非阻塞 | 帧传输，允许丢旧帧 |
| `SharedResult<T>` | AI 推理结果 | `atomic<shared_ptr>` 双缓冲，多读单写零锁 | 多消费者共享结果 |
| `std::atomic<T>` | 控制指令 | 无锁读写 | 单值 (pwm/speed/stop/steering_dir) |

**`SharedResult<T>` 关键设计**：
```cpp
template <typename T>
class SharedResult {
    // publish(): atomic_store(make_shared(move(data)))
    //   → 写者用新 shared_ptr 替换旧指针
    // get():     atomic_load() → shared_ptr<const T>
    //   → 读者获取 shared_ptr 副本，持有引用计数
    //
    // 核心保障：publish() 替换 _currentScene 后，正在 run() 的旧 scene
    //         仍被读者的 shared_ptr 持有 → 不会析构 → 线程安全
};
```

**`FrameQueue<T>` 关键设计**：
```cpp
template <typename T>
class FrameQueue {
    // produce():    队满时 pop_front + push_back，静默丢弃最旧帧
    // tryConsume(): 非阻塞，有数据返回 true + move，无数据立即返回 false
};
```

## 3. 数据预处理

预处理集中在 CaptureTask，推理任务不碰预处理：

| 输出队列 | 预处理 | 数据类型 | 说明 |
|----------|--------|----------|------|
| `segmentation_queue` | RGB直传 + resize(512×256) | UINT8 NHWC | 量化模型已 baked-in 归一化 |
| `detection_queue` | RGB直传 + resize(640×256) | UINT8 NHWC | 同上 |
| `display_queue` | 无处理（原始RGB工作帧） | UINT8 | 显示用，frame_crop后 |

```cpp
// 分割预处理 (CaptureTask 中):
cv::Mat seg_input;
cv::resize(frame, seg_input, cv::Size(seg_w, seg_h));
ctx_->segmentation_queue.produce(seg_input);
// frame已是RGB(共享内存原始格式)，无cvtColor
// 无 convertTo / subtract / divide — 量化模型已 baked-in 归一化
```

> **教训**: 量化 RKNN 模型 → `RKNN_TENSOR_UINT8`。若传 `RKNN_TENSOR_FLOAT32`，C API 按 float32 解析 INT8 量化权重 → 类型混淆 → SIGSEGV。

## 4. 线程模型

### 4.1 任务注册机制

采用**静态注册模式**，编译期自动注册到工厂：

```cpp
// 每个任务 .cpp 必须包含:
#include "MyTask.h"
#include "../thread/ThreadTaskFactory.h"
#include <memory>

REGISTER_THREAD_TASK(MyTask)
// 宏展开: static bool _thread_MyTask = [] {
//     ThreadTaskFactory::instance().reg("MyTask",
//         [](SharedContext* ctx) { return make_unique<MyTask>(ctx); });
//     return true; }();

MyTask::MyTask(SharedContext* ctx) : IThreadTask(ctx) {}
```

**注意**：
- 注册依赖静态变量初始化 → 新 `.cpp` **必须**加入 `CMakeLists.txt`，否则链接器不拉入 → "[Car] 未注册的线程任务"
- `REGISTER` 宏与构造函数之间不能有任何代码

### 4.2 线程生命周期与列表

```
Car::init()   ── 加载 JSON → 初始化 steering_dir → 初始化 PerspectiveMapper → 创建 ThreadPool (debug)
Car::start()  ── 按序 launchTask: Capture → Seg → Detect → Control → Display
                 启动 PerfStats 定时器 (5s 周期)
Car::stop()   ── stop=true → join 所有线程 → 销毁 ThreadPool
```

| 线程 | 频率 | 职责 |
|------|------|------|
| CaptureTask | 由 SHM 帧率决定 (~45fps) | SHM 采集 + flip + crop + 三分支预处理 |
| SegmentationTask | 双核流水线 (~80fps吞吐) | NPU Core1+Core2 交替推理 → argmax → resize → publish |
| DetectionTask | ~推理速度 (~50fps) | NPU Core0 推理 → PP-YOLOE后处理 → publish + scene切换 |
| ControlTask | 事件驱动 (~seg帧率) | cv.wait_for(50ms) → scene_manager.run() → UART |
| DisplayTask | 帧到达速度 (debug) | 叠加分割蒙版+检测框 → HTTP MJPEG推流 |
| PerfTimer | 5s 周期 | PerfStats::report() 打印性能报告 |

## 5. NPU 推理引擎

### 5.1 RKNNEngine 接口

```cpp
// 单 NPU 上下文 + 内部 worker 线程，每任务独立实例化
class RKNNEngine {
    using Result = std::pair<std::vector<cv::Mat>, int64_t>;
    //                推理结果                   纯rknn_run耗时(us)

    bool load(model_path, core_id, input_type = RKNN_TENSOR_UINT8);

    std::future<Result> submit(cv::Mat input);
    // 异步提交 — future 返回 (outputs, infer_us)
    // infer_us 为 worker 线程内记录的纯 rknn_run 耗时

    int inputWidth()  const;
    int inputHeight() const;

    // 内部: 1 个 rknn_context + 1 个 worker 线程:
    //   dequeue → rknn_inputs_set → t0 → rknn_run → t1 → clone → set_value({outputs, t1-t0})
};
```

### 5.2 性能计时体系

| 层级 | 计时内容 | 去向 |
|------|----------|------|
| RKNNEngine worker | 纯 `rknn_run` 耗时 (t1-t0) | 随 Result 传出 |
| Task 层 | `total_us` = 帧墙钟耗时；`infer_us` 从 engine 获取；`post_us` = CPU 后处理 | `recordStages(slot, total, infer, post)` |
| PerfStats | 每 5 秒汇总各槽位，分列打印 infer / post | `report()` |

**关键**: `total_us` 是帧墙钟时间而非 `infer + post` 之和（流水线重叠）。双核 Seg 的 total_us(~2ms) << infer_us(~25ms) 是正常的——推理在后台并行。

### 5.3 语义分割后处理

```cpp
// 模型输出: (1, 2, H, W) → cv::Mat(2, H*W, CV_32FC1)
// ch0 = 背景 logit, ch1 = 赛道 logit
const float* ch0 = out.ptr<float>(0);
const float* ch1 = out.ptr<float>(1);
cv::Mat mask(mh, mw, CV_8UC1);
for (int i = 0; i < mw * mh; i++)
    mask.data[i] = (ch0[i] >= ch1[i]) ? 0 : 1;  // argmax
cv::resize(mask, mask, Size(orig_w, orig_h), 0, 0, INTER_NEAREST);
```

### 5.4 目标检测后处理 (PPYoloEPostProcess.h)

```
PP-YOLOE anchor-based 后处理
  → 逐类置信度过滤 (config.ai.detection.confidence_threshold)
  → 坐标映射回工作帧 (scale_x/scale_y + crop_top)
  → 单类 NMS (config.ai.detection.nms_threshold)

类名/颜色从配置文件读取: config.ai.detection.classes / colors
```

### 6.3 场景切换 + 防抖 + 否决权

**DetectionTask 侧 — 提议 + 防抖**：

```cpp
// DetectionTask 每帧根据"图像最下方的目标"决定场景，带防抖:
//   NormalScene → 特殊场景: 即时切入
//   特殊场景 → 其他场景: 需检测连续N帧确认才切 (config.ai.detection.lost_frame_limit)

// SceneManager 仅在名称变化时真正切换:
ctx_->scene_manager.switchTo("CarScene");
// 同场景: 直接 return true，不创建新实例，PD 状态不丢失
```

**场景侧 — 否决权**：

```
需要阻止切换的场景（如超车中的 CarScene）可调用 hold() 锁住门闩，
DetectionTask 的 switchTo() 被拒绝后下帧会再试，直到场景 release() 放行。

  SceneManager::hold()    → _holding = true  （场景持有控制权，禁止切走）
  SceneManager::release() → _holding = false （放行，允许切换）
```

**SceneManager 侧 — 仲裁执行**：

```cpp
// switchTo 检查门闩：_holding==true → 拒绝切换 → DetTask 下帧再试
bool switchTo(const std::string& sceneName) {
    if (sceneName == _currentName) return true;
    if (_holding.load(acquire)) return false;   // 门闩挡着
    // ... 创建新场景 + atomic_store 替换 ...
}

// ControlTask 每帧执行:
auto scene = atomic_load(&_currentScene);
scene->run(ctx);  // 安全 — switchTo 替换 _currentScene 不影响当前调用
```

### 6.4 场景详细说明

#### NormalScene — 默认巡线

```
PathFollower::process()
    ↓ 宽鸟瞰变换: perspective.warp(seg_mask)
    ↓ 岔路处理: onFork() → handleFork(wide_mask, fork_keep_side, 1)
    ↓ 裁切中心区域: bird_width 范围
    ↓ 中线提取: onCenterline() → extractCenterline + smoothCenterline
    ↓ 丢线容错: onLost() → 盲开+速度衰减，超限停车
    ↓ 纯跟踪: findLookAhead() → 前视点
    ↓ 航向误差: headingError() → ppm_x/ppm_y 分离
    ↓ PD控制: onPD() → P*error + D*derivative, 首帧跳过D项
    ↓ 速度控制: onSpeed() → 大弯减速+加速平滑恢复
    ↓ steering_pwm.store() + target_speed.store()
```

#### CarScene — 车辆避让

- **触发**: DetectionTask 检测到 "car"
- **策略**: 重写 onCenterline，跳过车区像素行
- **流程**:
  1. 检测 car 框 → 四角转鸟瞰坐标 → 计算车占据区域 (car_rect)
  2. 扫描中线时，车区行跳过，从车框边界向外扫描
  3. 判断车在赛道哪侧 (左/右)，决定绕行方向

#### PersonScene — 行人避让

- **触发**: DetectionTask 检测到 "person"
- **策略**: 状态机 (停车等待 → 方向门控 → 冲刺)
- **流程**:
  1. 找最近行人 (y2最大)
  2. 人还远 (>5px): 正常巡线
  3. 人靠近 (≤5px): 停车等待，监控行人位置
  4. 方向门控: 左半区(点2→点1) 或 右半区(点3→点4)
  5. 门控完成: dashing_=true，冲刺通过
  6. 冲刺中人消失: 继续冲刺
  7. 没人且不在冲刺: 继续循线 (等DetectionTask切回)

#### RLightScene — 红灯停车

- **触发**: DetectionTask 检测到 "R_Light"
- **策略**: 动态停车阈值
- **流程**:
  1. 始终循线 (PathFollower)
  2. 检测 R_Light 框 → 底部中心转鸟瞰坐标
  3. 计算停车阈值: `stop_y = r_light_stop_y_cm/100*ppm_y + r_light_stop_speed_k*max_speed*ppm_y`
  4. 红灯 y ≥ 阈值 → target_speed = 0
- **配置**:
  - `r_light_stop_y_cm`: 基准停车位置 (默认40cm)
  - `r_light_stop_speed_k`: 速度系数 (默认0.5)

#### TrafficSignScene — 交通标志分岔

- **触发**: DetectionTask 检测到 "traffic_sign"
- **策略**: OCR识别 + 重写 onFork
- **流程**:
  1. 检测 traffic_sign 框 → 裁剪图像
  2. 调用 recognizeTrafficSign() → 0=直走(左), 1=右转(右)
  3. 设置 follower_.fork_side
  4. 正常巡线，onFork 使用 fork_side 选择赛道
- **OCR函数**: 空实现，后续接入大模型 API

## 7. 串口通信协议

### 7.1 帧格式 (类 Modbus)

```
┌──────┬──────┬──────┬────────────────────┬──────┐
│ HEAD │ ADDR │ LEN  │      PAYLOAD       │ CHK  │
│ 0x42 │ 1B   │ 1B   │   (LEN - 3) bytes  │ 1B   │
└──────┴──────┴──────┴────────────────────┴──────┘

校验和 = (HEAD + ADDR + LEN + PAYLOAD 各字节) 累加取低 8 位
```

### 7.2 指令表

| 地址 | 方向 | 内容 |
|------|------|------|
| `0x01` (CARCTRL) | 上位机 → 下位机 | speed(float32 LE, 4B) + pwm(uint16 LE, 2B) |
| `0x04` (BUZZER)  | 上位机 → 下位机 | sound(uint8, 1B) |
| `0x06` (KEY)     | 下位机 → 上位机 | 按键信号（急停/启动切换） |

### 7.3 串口配置

- 参数: 8N1, 无流控, 波特率由 JSON 配置
- 发送: `sendControl` / `sendBuzzer` 组帧 + 校验和
- 接收: 独立线程, VMIN=0 VTIME=5 (0.5s 超时), 帧同步 → 地址过滤 → 长度校验 → 校验和验证
- `consumeKeypress()`: `atomic<bool>` 消费并清零, ControlTask 轮询

## 8. 关键设计决策

| # | 决策 | 原因 |
|---|------|------|
| 1 | **预处理在采集线程** | 数据第一站集中转换，下游推理任务只做推理+后处理，避免重复计算 |
| 2 | **配置驱动，零硬编码** | 模型路径/尺寸/阈值/PID/类名/颜色全从 JSON 读；`j.contains` 向后兼容；改配置不动代码 |
| 3 | **量化模型 UINT8 直传** | RKNN 导出时已 baked-in 归一化参数；传 FLOAT32 导致类型混淆→段错误 |
| 4 | **NPU 核心隔离** | 检测→Core0；分割→Core1+2 双核流水线；每个任务独立 `RKNNEngine` 实例 |
| 5 | **static 注册模式** | 编译期自动注册类名到工厂，新增任务只需写 .cpp + 加 CMakeLists |
| 6 | **SharedResult 双缓冲** | `atomic<shared_ptr>` 读写零锁，读者持有旧数据期间不析构 |
| 7 | **FrameQueue 丢弃策略** | 队满丢最旧帧 → 消费者跟不上时自动降帧率，不阻塞生产者 |
| 8 | **Seg→Control 唤醒机制** | SegTask publish 后 `notify_one()`，ControlTask `cv.wait_for(50ms)` 阻塞等待；无新数据时零CPU |
| 9 | **赛道丢失盲开 + 停车保护** | 短暂丢线→盲开(方向保持+2×max_speed冲刺)；超限→stop停车 |
| 10 | **检测场景防抖** | 特殊场景间切换需N帧连续命中才执行，避免单帧漏检导致场景来回跳变 |
| 11 | **HTTP推流替代本地显示** | 纯socket MJPEG推流，支持浏览器远程查看；无需X11转发，适合SSH开发 |
| 12 | **场景切换否决权** | SceneManager 提供 hold()/release() 门闩，场景可阻止自己被切走（如超车未完成） |

## 12. 扩展指南

### 12.1 添加新线程任务

1. 创建 `tasks/MyTask.h` + `tasks/MyTask.cpp`（参照 `CaptureTask.cpp` 模板）
2. 将 `.cpp` 加入 `CMakeLists.txt` 的 `add_executable()` — **必须，否则注册不触发**
3. 在 `Car::start()` 中 `launchTask("MyTask")`
4. 如需新队列/共享结果，在 `SharedContext.h` 中声明

### 12.2 添加新场景

1. 在 `scene/scenes/` 下创建 `XxxScene.h` + `XxxScene.cpp`
2. 继承 `IScene`，实现 `run(SharedContext* ctx)`
3. 在 `.cpp` 中 `REGISTER_SCENE(XxxScene)`
4. 添加到 `CMakeLists.txt`
5. 在配置 `ai.detection.scene_map` 中添加映射
6. 在配置 `control.scene` 中添加场景参数

#### 场景继承模式

**简单场景** (直接使用 PathFollower):
```cpp
class XxxScene : public IScene {
    PathFollower follower_;
    void run(SharedContext* ctx) override {
        follower_.process(seg->mask, ctx);
    }
};
```

**复杂场景** (重写虚方法):
```cpp
class XxxScene : public IScene {
    class Follower : public PathFollower {
        int custom_state = 0;
        void onFork(cv::Mat& wide_mask, SharedContext* ctx) override;
    };
    Follower follower_;
};
```

#### 场景职责原则

- **场景只负责策略** (怎么巡线、怎么停车)
- **决策层在 DetectionTask** (何时切换场景)
- **场景内不主动切换其他场景**
- **场景始终执行巡线** (即使没检测到目标)
- **场景可 hold() 阻止切换** — 未完成任务时锁住门闩，完成后 release() 放行

### 12.3 添加新 AI 模型

1. 在配置中新增模型路径和尺寸字段
2. 创建对应 Task 类，使用独立 `RKNNEngine`
3. **确认数据类型**: 量化模型 → UINT8, 浮点模型 → FLOAT32，类型不匹配 = 段错误

### B. 性能统计槽位

| 索引枚举 | 名称 | 使用者 | 计时方式 |
|----------|------|--------|----------|
| `SLOT_CAPTURE = 0` | Capture | CaptureTask | `record(total)` |
| `SLOT_SEGMENTATION = 1` | Seg | SegmentationTask | `recordStages(total, infer, post)` |
| `SLOT_DETECTION = 2` | Detect | DetectionTask | `recordStages(total, infer, post)` |
| `SLOT_CONTROL = 3` | Control | ControlTask | `record(total)` |
| `SLOT_DISPLAY = 4` | Display | DisplayTask | `record(total)` |

- `total`: 帧墙钟耗时 (t_end - t_start)，用于 FPS 计算
- `infer`: RKNNEngine worker 记录的纯 `rknn_run` 耗时
- `post`: CPU 后处理耗时

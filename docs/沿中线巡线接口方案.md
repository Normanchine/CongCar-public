# 沿中线巡线接口方案（暂存）

> 版本: v1.0 | 状态: 方案暂存（代码未改动，当前仍沿边巡线） | 日期: 2026-08-14
> 目的: 记录"沿中线巡线"的备用接口设计，后续需要时可直接取用。

## 1. 背景

当前所有场景都沿边界巡线（`follow_edge_ = -1/0/+1`）。有一个备用需求：可能需要沿中线巡线（赛道左右边界的中间线），但**暂时未定用在哪、何时启用**。故只记录方案，不改代码。

## 2. 接口设计（方案）

在 `PathFollower` 的 public 区新增一个语义化入口：

```cpp
// PathFollower.h public 区
// 沿中线巡线（follow_edge_=0，extractBoundary 取左右边界中点）。
// 预留接口：当前默认沿边巡线，此方法暂未接入任何场景，供后续需要中线巡线时调用。
void setFollowCenterline() { follow_edge_ = 0; }
```

## 3. 为什么可以直接这样写

`follow_edge_` 取值已天然支持中线：

- `PathPlanning.h::extractBoundary(mask, centers, edge)`：
  - `edge < 0` → 取左边界 `left`
  - `edge > 0` → 取右边界 `right`
  - `edge == 0` → 取中点 `(left + right) * 0.5` ← **中线**
- `PathFollower::onPurePursuit` 参考点 `cx = w * (0.5f + target_cx_ratio)`，中线时 `target_cx_ratio = -0 * ratio = 0` → 参考点落到画面中心，纯跟踪沿中线前视，链路自洽。

## 4. 关键前提：中线必须经过 mask 等宽处理

**取中线强依赖等宽归一化**：

- 中线 = 每行左右边界中点 `(left + right)/2`，而**右边界最容易被分叉/碎片拉偏**（岔路外沿、干扰碎片都会把右边界拽走）。
- 必须先 `normalizeTrackWidth(mask)`（锚左调右，右边界归一化到平均宽度），再取中点，中线才是准的。

当前 `PathFollower::process` 顺序已经满足：

```cpp
// process() 内
normalizeTrackWidth(mask);           // 1.5 等宽归一化（无条件先做）
onCenterline(mask, centers, ctx);    // 3. 等宽后的 mask 取边界/中线
```

所以 `setFollowCenterline()` 落在等宽处理之后，是安全的。

## 5. 等宽处理对不同边界的影响（避坑）

| 巡线方式 | `follow_edge_` | 对等宽处理的依赖 |
|---------|---------------|-----------------|
| 沿左边界 | -1 | **不依赖**（等宽锚定左边界不动） |
| 沿中线 | 0 | **强依赖**（右边界须归一化，中线才准） |
| 沿右边界 | +1 | 强依赖（取的是归一化后的右边界） |

**注意**：如果以后某段赛道不能做等宽，则中线/右边界巡线都不能直接用，需另行处理。

## 6. 一个待办提醒（真要用时再处理）

`follow_edge_ = 0` 时，`PathFollower::onPD` 走 `follow_edge_ > 0` 为 false 的分支，即用**左边界那套 `pid_p/pid_d`**。如果以后中线巡线需要独立的 PD 参数，需在 `onPD` 加一个中线分支（`edge == 0` 时用单独系数）——现在不需要，暂不实现。
